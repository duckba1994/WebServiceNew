# GA / IM — ใบแจ้งเรื่อง (สร้าง · แก้ไข)

บันทึกฝั่งหน้าเว็บของสัญญา `GA-IM-create-frontend-guide.md` (repo ของ backend, อัปเดต 9 ก.ย. 2026)
ไฟล์นี้เก็บเฉพาะสิ่งที่คนแก้โค้ดหน้าเว็บต้องรู้ ไม่ใช่สำเนาคู่มือทั้งฉบับ

## 1. สองโมดูล หนึ่งชุดโค้ด

| โมดูล | base path | master | แผนกปลายทาง |
|---|---|---|---|
| GA (ธุรการ) | `/api/v1/GARequest` | `/api/v1/MasterData/ga` | 06 |
| IM (ซ่อมบำรุง) | `/api/v1/IMRequest` | `/api/v1/MasterData/im` | 18 |

payload เหมือนกันทุกช่อง ต่างแค่ base path กับลิสต์ "เรื่องที่แจ้ง"
ฝั่งหน้าเว็บจึงมีไฟล์เดียวต่อหน้าที่ แล้วรับ `module` เข้าไปเป็นพารามิเตอร์:

- `src/api/deptRequest.ts` — POST / GET / PUT (+ `isDeptRequestModule()`)
- `src/data/deptRequestForm.ts` — ฟอร์ม → payload ตอนสร้าง
- `src/hooks/useDeptRequest.ts` — GET ใบแบบเต็มฟอร์ม
- `src/data/requestEdit.ts` — `GA_IM_EDIT_FIELDS` + `toDeptUpdatePayload()`

**ห้ามแยกเป็นสองชุด** ถ้าวันหนึ่งสองโมดูลต่างกันจริง ให้เพิ่มพารามิเตอร์ ไม่ใช่ก๊อปไฟล์

## 2. กับดักที่ต้องรู้

- **รายละเอียดยาวได้ 500 ตัวอักษร ไม่ใช่ 1000** (คอลัมน์ในฐานสั้นกว่า PL/IT)
  ค่านี้อยู่ที่ `DEPT_DETAIL_MAX_LEN` ใน `data/requestForm.ts` ใช้ทั้งฟอร์มสร้างและฟอร์มแก้ไข
- **ห้ามโชว์เลขที่ใบก่อนกดบันทึก** API ออกเลขตอน insert จริงเท่านั้น
  (เว็บเก่าโชว์ตัวอย่างไว้แล้วเลขจริงมักไม่ตรง เพราะมีคนกดบันทึกแทรก)
- ปีในเลขที่ใบ (`GA-BC-26-003`) มาจาก **ปีปัจจุบันของเครื่อง ไม่ใช่ปีของ `docDate` ที่ผู้ใช้กรอก**
  กรอกวันที่ย้อนไปปีที่แล้วก็ยังได้เลขของปีนี้ — ตามพฤติกรรมเว็บเก่า
- **master ของ IM มี `id` ซ้ำ** สองแถวเป็น `id = 5` ("ขายทรัพย์สิน" / "ขายซาก") และไม่มี `id` 6
  → ห้ามใช้ `id` เป็น key ของลิสต์ · ค่าที่ส่งกลับ API คือ `name` ทุกลิสต์อยู่แล้ว
- **ไม่มีเส้นอัปโหลดไฟล์** สองโมดูลนี้ไม่มีคอลัมน์เก็บไฟล์ในฐาน
  `attachmentApiOf()` จึงคืนทะเบียนเปล่า และกล่อง "รูปภาพ" ไม่ขึ้นเลย
- ช่อง `attachBudget` / `attachExBudget` / `attachSpec` / `attachQuatation` เป็น **เช็คลิสต์ติ๊ก**
  ไม่ใช่ไฟล์แนบ · สะกด `Quatation` ตาม API ห้ามแก้
- หน่วยงานผู้แจ้ง: รหัส `"01"` เป็น placeholder **ห้ามส่ง** (API ตอบ 400 "เลือกหน่วยงานก่อนเสมอ")
  หน้าเว็บไม่ส่ง `departid` เลย ให้ backend ใช้ค่าจาก token
- `jobStatus` จาก POST/PUT เป็นตัวเลขดิบในฐาน — **หน้ารายการให้เชื่อค่าจาก `/Requests/...` เสมอ**

## 3. ใครแก้ได้ — แคบกว่า PL มาก

| ขั้นที่ใบค้างอยู่ | ใครแก้ได้ |
|---|---|
| รอ Mgr อนุมัติ (`Approved-Request`) | หน่วยงานผู้แจ้งเท่านั้น |
| รอรับเรื่อง (`Receive-Request`) | **ไม่มีใครแก้ได้** |
| รอดำเนินการเพื่อปิดงาน (`Service And Close-Job`) | แผนกปลายทางเท่านั้น (06 / 18) |
| ปิดงานแล้ว · ยกเลิกแล้ว | ไม่มีใครแก้ได้ |

**หน้าเว็บไม่คำนวณเงื่อนไขนี้เอง** — อ่าน `canEdit` จาก `GET /{module}Request/{docNo}` อย่างเดียว
(`isApiEditGated()` ใน `data/requestEdit.ts` เป็นตัวคัดว่าโมดูลไหนใช้กติกานี้)

⚠️ ต้องเป็น `true` **เป๊ะ ๆ** ไม่ใช่ `!== false` แบบโมดูลอื่น — ที่นี่ไม่มีกติกาหน้าเว็บมาค้ำ
`undefined` (ยังโหลดไม่เสร็จ / โหลดไม่ติด) จึงต้องแปลว่า "ยังแก้ไม่ได้"

⚠️ **409 เกิดได้แม้ `canEdit` เพิ่งบอกว่า `true`** เพราะระหว่างนั้นอาจมีคนกดอนุมัติไปแล้ว
→ จับ 409 แล้วโหลดใบใหม่เสมอ (`refreshTick` ใน `RequestDetailModal`)

## 4. กติกาของ PUT

- `requestBy` กับ `requestDetail` **บังคับส่งทุกครั้ง** แม้ผู้ใช้ไม่ได้แก้
- ฟิลด์อื่นที่ไม่ส่ง / เป็น `null` = **ไม่เปลี่ยน** · สตริงว่าง = **ล้างค่า**
- ไม่ส่ง `departid` โดยตั้งใจ — ส่งค่าใหม่ = ใบย้ายหน่วยงาน แถว workflow ขั้นรออนุมัติย้ายตาม
  แล้วแผนกเดิมแก้ใบตัวเองไม่ได้อีก
- `site` แก้ไม่ได้ (ผูกกับเลขที่เอกสารที่ออกไปแล้ว) · `docDate` เขียนลงทั้งวันที่เอกสารและวันที่แจ้ง
- `lines`: ไม่ส่ง/`null` = ไม่แตะของเดิม · `[]` = ลบหมด · array = **sync ทั้งชุด**
  แถวเดิมต้องหิ้ว `recNo` ไปด้วย **แถวที่ไม่ได้ส่งกลับมาจะถูกลบ**
  ช่อง `received` / `cancel` / `cancelBy` / `cancelDate` แก้ผ่านเส้นนี้ไม่ได้

## 5. "สิ่งที่แนบมาด้วย" — กรอกตอนสร้างใบ และคอลัมน์ของ GA สลับ

เช็คลิสต์ 4 ข้อ อยู่ท้ายกล่อง "เรื่องที่แจ้ง" ของฟอร์มสร้างใบ (ผู้ใช้ตัดสิน 9 ก.ย. 2026 —
เคยวางไว้ที่ขั้นเอกสารแนบ/อนุมัติ แล้วย้ายมา) ป้ายทั้งชุดยึดตามหน้าเก่าของ IM

เรนเดอร์เป็น "รายการแนวตั้งในกรอบเดียว" ไม่ใช่ปุ่มติ๊กแบบเรียงต่อกันเหมือนฟิลด์ checkboxes อื่น
และช่องเลขที่เอกสารโผล่ **ในบรรทัดเดียวกับข้อที่ติ๊ก** (`FieldDef.optionFields`)
ของเดิมในหน้า ASPX แยกช่องติ๊กไว้คอลัมน์ซ้าย เลขที่เอกสารไว้คอลัมน์ขวา แล้วอ่านไม่ออก
ว่าเลขที่ช่องไหนคู่กับข้อไหน (ผู้ใช้ทัก 9 ก.ย. 2026) — อย่าเปลี่ยนกลับ

ฟิลด์ลูกยังต้องมี `showWhen.includes` กำกับไว้ด้วย เพราะนั่นคือตัวที่ทำให้ `validateRequestForm`
ข้ามช่องบังคับกรอกที่เจ้าของยังไม่ได้ติ๊ก ส่วน `optionFieldKeys()` เป็นตัวกันไม่ให้ฟิลด์ลูก
ถูกเรนเดอร์เป็นแถวของตัวเองซ้ำอีกรอบ

⚠️ **ช่องเลขที่ของ GA เก็บสลับคอลัมน์กับ IM** ตรวจจากไฟล์เว็บเก่าโดยตรง:

| หน้า | ป้าย | control | คอลัมน์ |
|---|---|---|---|
| `BC_GA_Request_Add.aspx` | เลขที่งบประมาณ | `txtExBudget_DocNo` | **ExBudgetDocNo** |
| | เลขที่อนุมัตินอกงบ | `txtBudget_DocNo` | **BudgetDocNo** |
| `BC_IM_Request_Add.aspx` | งบประมาณเลขที่ | `txtBudget_DocNo` | BudgetDocNo |
| | ใบขออนุมัติงบประมาณเลขที่ | `txtExBudget_DocNo` | ExBudgetDocNo |

code-behind ของทั้งสองหน้าผูก control กับคอลัมน์ตรงตัว 1:1 ตัวที่สลับคือป้ายในไฟล์ `.aspx`
ใบเก่าของ GA จึงเก็บเลขงบประมาณไว้ในคอลัมน์ `ExBudgetDocNo` จริง ๆ (ใบ PL ก็เป็นแบบเดียวกัน)
**ห้ามจัดให้เหมือนกันเพื่อความสวยงาม** — ทำแล้วใบเก่าของ GA จะโชว์เลขสลับช่อง
และเว็บเก่ากับเว็บใหม่จะเล่าคนละเรื่องระหว่างที่ยังใช้คู่กัน

⚠️ ช่องติ๊ก (`Attach_Budget` / `Attach_ExBudget`) **ไม่สลับ** ทั้งสองแผนก — สลับแค่ช่องเลขที่

จุดเดียวที่รู้เรื่องนี้คือ `swapsDocNo()` ใน `data/deptRequestForm.ts` และ `DeptAttachList`
ในหน้ารายละเอียดที่อ่านกลับด้วยกติกาเดียวกัน วันไหน backend ย้ายข้อมูลของ GA ให้ตรงป้ายแล้ว
ให้ลบเงื่อนไข GA ออกจากสองที่นี้

## 5.1 ช่องที่ยังไม่อยู่บนหน้าเว็บ

`remark` (หมายเหตุ) ยังไม่มีช่องที่ไหนเลย และฟอร์มแก้ไขก็ยังไม่แตะเช็คลิสต์
`toDeptUpdatePayload()` จึงไม่ส่งทั้งสองอย่างขึ้นไป ค่าที่บันทึกไว้ตอนสร้างจึงไม่ถูกเขียนทับ
— ต่างจากใบ PL ที่ต้องหิ้วค่าเดิมกลับไปกับ PUT ทุกครั้ง

ยังไม่มีในสัญญา: ไม่อนุมัติ / ยกเลิกใบ; ชุดแท็บ GA/IM ดู §7

## 6. Error ที่ต้องรองรับ

| HTTP | ความหมาย | ทำอะไรต่อ |
|---|---|---|
| 400 | ข้อมูลไม่ผ่าน (ไม่กรอกรายละเอียด, หน่วยนับไม่รู้จัก, จำนวนไม่เกิน 0) | โชว์ `message` ตรง ๆ เป็นภาษาไทยพร้อมโชว์ ระบุลำดับแถวมาให้ด้วย |
| 401 | token หมดอายุ | `apiFetch` ยิง `auth:unauthorized` ให้แล้ว |
| 403 | หน่วยงานไม่ตรงกับขั้นตอน | โชว์ `message` แล้วปิดปุ่มบันทึก |
| 404 | ไม่พบเลขที่เอกสาร | กลับหน้ารายการ |
| 409 | ใบอยู่ในขั้นที่แก้ไม่ได้แล้ว | โชว์ `message` แล้ว `GET` ใหม่เพื่อรีเฟรช `canEdit` |


## 7. รับเรื่องและดำเนินการ — เชื่อม API แล้ว (9 ก.ย. 2026)

สัญญาจริง: [GA_IM_SERVICE_FRONTEND_GUIDE.md](GA_IM_SERVICE_FRONTEND_GUIDE.md)

- ทั้ง GA/IM ใช้ General / รับเรื่อง / ดำเนินการ; approve อยู่ General
- receive ไม่มี fields; saveService บันทึกซ้ำโดยไม่เลื่อนขั้น; service ปิดใบ
- ผู้ใช้ปรับ UX 9 ก.ย. 2026: ทั้ง GA และ IM ใช้ปุ่ม “ดำเนินการเสร็จ” กดแล้วส่ง service ทันทีหลังตรวจฟอร์ม ไม่ยืนยันซ้ำ
- ปุ่มและสิทธิ์ยึด availableActions; ปิดใบยึด phase ไม่ใช่ JobStatus
- ตัวเลือกคงข้อความตรงตามคู่มือฉบับที่ผู้ใช้ส่งมา (ไม่มี endpoint สำหรับตัวเลือกในสัญญานี้)
- ส่ง repairStatus / exPrNo / workResults / remark และ leadTime เฉพาะ GA (0–100)
- อ่าน workResults จาก resolution.solution, remark จาก item.remark, leadTime จาก resolution.leadTime
- ผู้ดำเนินการเป็น read-only: servicedBy / servicedDate ประทับจาก JWT/server เมื่อ service เท่านั้น
- ส่งสตริงว่างเพื่อล้างข้อความโดยเจตนา ห้ามใช้ cleanFieldValues ของโมดูลอื่น
- leadTime ว่าง = ไม่ส่งเพื่อคงค่าเดิม; 0 ต้องส่งเป็นตัวเลข ไม่หายไปเพราะ falsy
- สำเร็จใช้ response.item; 409 โหลดรายละเอียดใหม่ ไม่ retry action อัตโนมัติ
- โค้ดฟอร์มแยกใน GaImServicePanel.tsx และ data/deptServiceForm.ts ใช้ร่วมกันทั้งสองโมดูล
