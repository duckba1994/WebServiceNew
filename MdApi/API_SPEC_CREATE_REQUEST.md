# API SPEC — สิ่งที่เหลือของ "สร้างใบแจ้งเรื่อง" (insert + combobox)

> อัปเดต 6 ก.ย. 2026 · หน้าเว็บสร้างครบทุกแผนกแล้ว เหลือฝั่ง backend 2 อย่างคือ
> **endpoint สร้างใบ (insert)** กับ **endpoint ตัวเลือก (combobox / master data)**
>
> ⚠️ ชื่อฟิลด์ใน payload ด้านล่างเป็น **ข้อเสนอ** ที่ล้อตาม `POST /PLRequest` ของเดิม
> backend ตั้งชื่อจริงเป็นอะไรก็ได้ — บอกมาแล้วหน้าเว็บจะใช้ชื่อนั้นเป๊ะ ๆ (ดู `API_NAMING.md`)
> หน้าเว็บ **ไม่เดาชื่อฟิลด์เอง**

## 2. combobox (master data)

สเปกอยู่ใน **`API_SPEC_DEPT_MASTER.md`** แล้ว — เส้นเดียวต่อแผนก คืนหลายชุดในก้อนเดียว
สรุปว่าแต่ละแผนกต้องส่งชุดไหนบ้าง:

| แผนก | ชุดที่ต้องส่ง |
|------|----------------|
| HR | `requestTypes` (เรื่องที่แจ้ง) |
| GA / IM | `types` (ประเภท) + `requestTypes` (เรื่องที่แจ้ง) |
| AF | `requestTypes` |
| SV | `requestTypes` |
| SQA | `types` + `requestSubTypes` (ผูกกันด้วย `typeId`) |
| PS | `types` + `requestTypes` + `estimates` (ใบประเมินราคา) |

- **ส่วนงาน (HV/FL) ไม่ต้องส่ง** — ทุกฟอร์มอ่านจาก `/MasterData/cr` เส้นเดียว
  แต่ `section` ที่ผูกมากับแถวอื่นต้องใช้โค้ดชุดเดียวกัน
- ค่าที่ฟอร์มเก็บและจะส่งกลับตอน insert = **`name`** ไม่ใช่ `id`

## 3. insert — รูปแบบที่หน้าเว็บคาดหวัง (ล้อตาม `PLRequest`)

```
POST /api/v1/{แผนก}Request
Authorization: Bearer <token>
→ 201 Created  { "docNo": "...", ... }
```

- **หัวใบที่ไม่ต้องส่ง** ให้ backend เติมจาก token / เวลาปัจจุบันเหมือน PL:
  `requestBy` (ชื่อผู้แจ้ง) · `departid` (หน่วยงานผู้แจ้ง) · `site` · `docDate`
  หน้าเว็บส่งเฉพาะสิ่งที่ผู้ใช้กรอกจริง
- **เลขที่เอกสารออกตอนบันทึกเท่านั้น** ไม่มีเส้นจองเลขล่วงหน้า และหน้าเว็บแสดงเลขจาก response
  (บทเรียนจาก CR — เลขที่พรีวิวไว้ไม่ตรงกับที่บันทึกจริง)
- **บันทึกไม่ผ่าน = ย้อนกลับทั้งใบ** (เลขที่ด้วย) กดซ้ำได้ปลอดภัย
- **ข้อความ error เป็นภาษาไทยใน body** หน้าเว็บเอาไปแสดงตรง ๆ (`ApiError.message`)
  400 ที่เกี่ยวกับรายการย่อยควรบอกลำดับแถว เช่น "รายการที่ 2 จำนวนต้องมากกว่า 0"

### รายการย่อย (`lines`) — แผนกที่มีกล่อง "รายการที่ขอ"

GA / IM / AF / SV / PS ใช้ตารางแบบเดียวกับ PL (ไม่มีช่องราคา) — ส่งเป็น array เดียวกับหัวใบ

```jsonc
"lines": [ { "item": "…", "qty": 2, "unit": "ชิ้น", "remark": "…" } ]
```

ไม่มีแถวที่กรอกชื่อรายการ = ไม่ต้องส่ง `lines` (ทุกแผนกกล่องนี้ไม่บังคับ)

## 4. insert — ฟิลด์ที่ฟอร์มเก็บ แยกรายแผนก

คอลัมน์ "คีย์ในฟอร์ม" คือชื่อที่หน้าเว็บใช้อยู่ตอนนี้ ใช้เป็นตัวตั้งต้นของชื่อฟิลด์ใน payload ได้

### HR (`HR-PR`)

| คีย์ในฟอร์ม | ป้ายไทย | บังคับ | ที่มา |
|---|---|---|---|
| `reporterName` | ชื่อ-นามสกุล | ✅ | login (ไม่ต้องส่งก็ได้) |
| `position` | ตำแหน่ง | ✅ | ผู้ใช้พิมพ์ (≤100) |
| `topic` | เรื่องที่แจ้ง | ✅ | master `/hr` → `requestTypes` (ส่งเป็นชื่อ) |
| `detail` | รายละเอียด | ✅ | ผู้ใช้พิมพ์ (≤1000) |

### GA / IM

| คีย์ในฟอร์ม | ป้ายไทย | บังคับ | ที่มา |
|---|---|---|---|
| `requestType` | ประเภท | ✅ | master `types` (ชื่อ) |
| `topic` | เรื่องที่แจ้ง | ✅ | master `requestTypes` (ชื่อ) |
| `dueDate` | วันที่ต้องการใช้งาน | ✅ | วันที่ (ISO) |
| `topicDetail` | ระบุเรื่องที่แจ้ง | ✅ | ≤1000 |
| `items` | รายการที่ขอ | — | `lines` |

### AF

เหมือน GA/IM แต่ **ไม่มี** `requestType` และ **ไม่มี** `topicDetail` — เหลือ `topic` + `dueDate` + `lines`

### SV (`SV-HV`)

| คีย์ในฟอร์ม | ป้ายไทย | บังคับ | ที่มา |
|---|---|---|---|
| `customerType` | ประเภทเรื่องที่แจ้ง | ✅ | "ลูกค้าภายนอก" / "หน่วยงานภายในองค์กร" (ข้อความ) |
| `customerDept` | หน่วยงานที่ขอใช้บริการ | ✅ เมื่อเลือกภายใน | **`departid`** จาก `/MasterData/departments` (ไม่ใช่ชื่อ) |
| `section` | ส่วนงาน | ✅ | โค้ด `HV` / `FL` |
| `topic` | เรื่องที่แจ้ง | ✅ | master `/sv` → `requestTypes` (ชื่อ) |
| `attachedDocs` | สิ่งที่แนบมาด้วย | — | ติ๊กหลายข้อ — หน้าเว็บส่งเป็นข้อความคั่นด้วย `,` ได้ หรือแยกเป็น boolean ต่อข้อก็ได้ (บอกมา) |
| `attachedOther` | ระบุสิ่งที่แนบมาด้วย | ✅ เมื่อติ๊ก "อื่นๆ" | ≤100 |
| `items` | รายการที่ขอ | — | `lines` |
| `photos` | รูปภาพ | — | ต้องมี endpoint แนบรูปแบบ IT/PL (`ImgPath1..3`) |

⚠️ 4 ฟิลด์แรกยังไม่มีที่เก็บฝั่ง DB (ยกมาจาก `API_SPEC_DEPT_MASTER.md` §5)

### SQA (`SA`)

| คีย์ในฟอร์ม | ป้ายไทย | บังคับ | ที่มา |
|---|---|---|---|
| `section` | ส่วนงาน | ✅ | โค้ด `HV` / `FL` |
| `requestType` | ประเภทเรื่องที่แจ้ง | ✅ | master `types` (ชื่อ) |
| `requestSubType` | รายละเอียดที่แจ้ง | ✅ | master `requestSubTypes` (ชื่อ) |
| `dueDate` | วันที่ต้องการใช้งาน | ✅ | วันที่ (ISO) |
| `detail` | รายละเอียด | ✅ | ≤1000 |

### PS

| คีย์ในฟอร์ม | ป้ายไทย | บังคับ | ที่มา |
|---|---|---|---|
| `requestType` | ประเภท | ✅ | master `types` (ชื่อ) |
| `topic` | เรื่องที่แจ้ง | ✅ | master `requestTypes` (ชื่อ) |
| `priceDate` | วันที่ต้องการราคา | ✅ | วันที่ (ISO) |
| `planPriceDate` | Plan วันที่ต้องการราคา | — | วันที่ (ISO) — ยังต้องยืนยันว่าผู้แจ้งกรอกเอง หรือฝั่ง PS เติมทีหลัง |
| `dueDate` | วันที่ต้องการใช้งาน | ✅ | วันที่ (ISO) |
| `topicDetail` | ระบุเรื่องที่แจ้ง | ✅ | ≤1000 |
| `estimateNo` | เลขที่ใบประเมินราคา | — | `docNo` จาก master `estimates` |
| `items` | รายการที่ขอ | — | `lines` |

ข้อมูลเครื่องจักร 9 ช่องใต้เลขที่ใบประเมินราคาเป็น **อ่านอย่างเดียว** หน้าเว็บเติมจากใบที่เลือก
**ไม่ต้องรับกลับ** — อ่านจากใบประเมินราคาฝั่ง DB ได้เลย
